# tray-run

Держит несколько долгоживущих консольных команд скрытыми и управляет ими из одной иконки в трее: показать консоль, спрятать, перезапустить, остановить.

## Зачем

Сборки, серверы, watch-процессы, `ping -t` занимают окна и панель задач. `tray-run` прячет их, оставляя нативный консольный вывод доступным по запросу, и следит за падениями: упавшее приложение поднимается с нарастающей паузой, а безнадёжно падающее останавливается и ждёт ручного запуска.

## Быстрый старт

Создайте `%APPDATA%\tray-run\config.toml`:

```toml
[app.dev-server]
command = "npm run dev"
dir = "C:/projects/web"

[app.build]
command = "cargo watch -x build"
dir = "C:/projects/app"
```

Запустите `tray-run.exe` без аргументов. В трее появится иконка, в меню — оба приложения.

## Справка

`tray-run.exe --help` печатает полное руководство: запуск и ключи, опции конфига с умолчаниями, пункты меню трея, автозапуск, логирование и ограничения. Текст вшит в бинарник, исходники не нужны. Если консоли нет (запуск двойным кликом), справка показывается в окне сообщения.

`tray-run.exe --version` печатает версию.

## Конфиг

Файл ищется в таком порядке:

1. `--config PATH`
2. переменная окружения `TRAY_RUN_CONFIG`
3. `%APPDATA%\tray-run\config.toml`
4. `tray-run.toml` рядом с `tray-run.exe`

Порядок приложений в меню — как в файле.

```toml
[defaults]
restart = "on-crash"            # never | on-crash | always
start_hidden = true
restart_gap_ms = 2000           # базовая пауза перед перезапуском
restart_backoff_max_ms = 60000  # потолок паузы
restart_max = 5                 # падений подряд до отказа, 0 = без предела
restart_reset_ms = 60000        # столько проработал — считается стабильным

[app.name]
command = "npm run dev"         # обязательно
dir = "C:/projects/web"         # рабочий каталог, по умолчанию — каталог, из которого запущен tray-run.exe
restart = "always"              # переопределяет defaults
start_hidden = false
```

Ключи `[defaults]` действуют на все приложения, ключи `[app.*]`, кроме `command` и `dir`, их переопределяют. Неизвестный ключ — ошибка конфига, опечатка не проходит молча.

`command` — строка, разбирается по правилам Windows: путь с пробелами берите в кавычки, как в `.bat`:

```toml
command = "\"C:\\Program Files\\nodejs\\node.exe\" server.js"
```

## Управление

Одна иконка на все приложения. Левый и правый клик открывают одно меню:

- подменю на приложение — _Show console / Hide console_, _Restart_, _Stop_
- `name — stopped` или `name — gave up after 3 crashes` — приложение не работает, доступен _Start_
- `name (2 restarts, next in 8s)` — ждёт перезапуска после падения
- _Reload config_ — перечитать конфиг: новые приложения поднимаются, удалённые и изменённые перезапускаются, неизменённые не трогаются
- _Install autostart / Remove autostart_
- _Quit_ — завершить все приложения и выйти

Закрытие окна консоли руками считается намеренной остановкой: приложение помечается `stopped` и само не поднимается.

## Автозапуск

```sh
tray-run.exe --install-startup
tray-run.exe --uninstall-startup
```

Пишется одна запись `tray-run` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, в Task Manager Startup видно одно осмысленное имя — за ним все приложения из конфига. То же доступно из меню трея.

## Один экземпляр

Одновременно работает только один `tray-run.exe`: второй экземпляр покажет сообщение и выйдет. Правки конфига подхватывает _Reload config_ в меню трея: новые приложения поднимаются, удалённые останавливаются, изменённые перезапускаются, неизменённые не трогаются.

Неизвестный ключ (например `--nmae`) печатает usage и завершается с кодом 2.

## Сборка из исходников

Нужен Rust (MSVC toolchain) для Windows.

```sh
cargo build --release
```

Бинарник: `target\release\tray-run.exe`.

`just install` собирает release, кладёт бинарник в `~/bin` и перезапускает запущенный экземпляр с теми же аргументами (включая `--config`).

## Как это работает

- Каждая команда запускается через `conhost.exe` с `CREATE_NEW_CONSOLE | CREATE_SUSPENDED` и `wShowWindow = SW_HIDE`: консоль создаётся скрытой, но остаётся настоящим окном `conhost` — с выделением, копированием и обычным рендерингом
- Окно ищется через `EnumWindows` (класс `ConsoleWindowClass`, принадлежащий запущенному `conhost`)
- Процесс `conhost` и его потомки живут в Job Object с `KILL_ON_JOB_CLOSE`
- Код возврата берётся у дочернего процесса, а не у `conhost`: сам `conhost` всегда выходит с нулём
- Обёртка — GUI-процесс (`windows_subsystem = "windows"`), своего окна нет; трей и меню сделаны через `Shell_NotifyIconW` напрямую

## Диагностика

`TRAY_RUN_LOG` — путь к файлу, туда пишется лог стартов, падений и перезапусков:

```powershell
$env:TRAY_RUN_LOG = "$env:TEMP\tray-run.log"
tray-run.exe
```

## Ограничения

- Windows only: conhost, трей и Job Objects
- Команда, которая завершается быстрее, чем находится её окно, определяется по коду возврата, но своё окно показать не успевает
